# Kapitelplan

## Övergripande progression

Planen går från strategisk målbild till plattformsarkitektur, vidare till data, köer och state, därefter moderniseringsmönster och slutligen governance och målarkitektur.


## Del 1: Målbild och moderniseringsresa

### Kapitel 1: Varför cloud native för Java EE?
- Syfte: Målbild, drivkrafter och skillnaden mellan containerized och cloud native.
- Läsarens förkunskaper: Erfarenhet av Java EE, enterprise-arkitektur och traditionell drift.
- Nya huvudbegrepp: Introduceras kontrollerat i kapitlets canon.
- Återkommande scenario: Modernisering av en Java EE-, Oracle- och IBM MQ-baserad plattform till OpenShift.
- Ersättning för övningar: Beslutsguide, tradeoff-analys, anti-patterns och arkitektens checklista.
- Svårighetsgrad: Erfaren.
- Bygger vidare på: Tidigare beslut, begrepp och moderniseringscase.

## Progressionskontroll
- Begrepp introduceras från målbild till plattform, därefter state, integration och governance.
- Kapitel ska inte använda nya begrepp som om de redan vore etablerade utan kort introduktion.
- Varje kapitel bör introducera högst 1–3 huvudbegrepp.
- Praktiska moment ersätts normalt med beslutsstöd, checklistor och arkitekturella vägval.
- Slutkapitlet samlar målarkitektur och roadmap.
